## Procedure exports and exact linking

Before the fix, `check_in`, `claim`, and `deposit` were methods on the
`#[component]` trait without `#[account_procedure]`. SDK 0.14's migration guide
specifies that methods are not implicitly account-interface procedures; the
marker is required on the trait declaration. The VM had reported missing roots
`0x28c6e35365e6ebdb917aaedf1c18f671bdb8e91f5dcdb5b4c5d69cd08b0e895b` and
`0x6fdea170932e1c163e0059cfb9838c1635b66cb5ac76f3f3527230bf48737b29`. Those
historical runtime errors did not associate each root with a specific note
package, so no per-note mapping is inferred from them.

The three callable methods now have `#[account_procedure]` on the trait. The
installed stable-runtime account procedure roots from the rebuilt vault package
are:

| Procedure | Root |
| --- | --- |
| check-in | `0xea1f6259b973229098c56687ed29331e1571e4e129a877ed29c5b281e2df4116` |
| claim | `0x1a675e57ecc6f1b449089d046fc5220edbeb06defea2cffe15477e35e9355692` |
| deposit | `0x2e4db51532ed223c53c88db69df5bca1e241a27f1de4c3c8c46c9c08743516dc` |

`integration/examples/procedure_roots.rs` reads the stable `AccountComponent`
metadata and MASTs. It asserts each note package declares the exact rebuilt
`heirbeat-vault` component package digest and that its external procedure roots
contain exactly the matching installed procedure root. All three checks pass.
Note projects link the component by local package path in their Miden project
dependency metadata; no roots are hardcoded in note code.

Stale `target/miden*`, generated-WIT and bundled-WIT directories for these
contracts were removed before rebuilding. The compiler emitted no standalone
Heirbeat WIT file; the rebuilt note `.masp` manifests and MASTs embed the
component dependency digest and corresponding external procedure root. The
standard SDK `miden.wit` bundle was regenerated. There are no hand-edited
generated bindings.
